Conceptos y fundamentos teóricos

Antes de escribir ningún comando conviene tener claro qué vas a instalar y por qué. Esta sección explica las ideas en lenguaje llano, con analogías, y sin dar por sabido nada.

1. ¿Qué es React?

React es una librería de JavaScript orientada a la creación de interfaces de usuario interactivas basadas en componentes reutilizables.

Una forma sencilla de imaginarlo: React convierte la pantalla en un conjunto de piezas independientes, como bloques de construcción. Una pieza puede ser un botón, otra una tarjeta, otra una barra de navegación. Cada pieza se escribe una vez y se puede reutilizar en cualquier parte.

Pero atención: React por sí solo opera principalmente en el navegador del cliente (Client-Side Rendering). Eso puede complicar la optimización para motores de búsqueda (SEO) y la velocidad de carga inicial en aplicaciones complejas.

2. ¿Qué es Next.js y por qué usarlo con React?

Next.js es un framework (marco de trabajo) full-stack construido sobre React. Proporciona herramientas listas para usar:

  • Enrutamiento automático basado en el sistema de archivos.
  • Optimización de imágenes y de fuentes tipográficas.
  • Renderizado en el servidor (Server-Side Rendering).
  • Creación de APIs de backend integradas en el mismo proyecto.

Dicho de otro modo: React te da las piezas y Next.js te da la fábrica, el transporte y la tienda donde se muestran esas piezas.

3. Renderizado en servidor (SSR) frente a renderizado en cliente (CSR)

CSR — Client-Side Rendering

El servidor envía un archivo HTML prácticamente vacío y un paquete grande de JavaScript. El navegador descarga ese JavaScript y genera la interfaz en tiempo real.

Consecuencia: la carga inicial puede ralentizarse en dispositivos lentos y el contenido tarda más en ser visible para los buscadores.

SSR — Server-Side Rendering

Next.js procesa los componentes en el servidor y envía al navegador un documento HTML ya construido con el contenido listo.

Consecuencia: mejora de forma notable el SEO y se reduce el tiempo de espera del usuario.

→

→

4. El App Router y los React Server Components

A partir de la versión 13, Next.js introdujo el App Router, un paradigma basado en la carpeta src/app.

Todos los componentes que viven dentro del App Router son React Server Components (RSC) por defecto. Eso significa que se ejecutan exclusivamente en el servidor, sin añadir código JavaScript innecesario al navegador del cliente.

Cuando un componente necesita interactividad (por ejemplo, un contador que cambia al pulsar un botón), se marca con la directiva 'use client'; en su primera línea y pasa a ser un Client Component.

6. Las herramientas que vas a instalar

Node.js

Entorno de ejecución de JavaScript fuera del navegador. Es la base sobre la que funcionan todas las herramientas de construcción de Next.js.

npm

Node Package Manager. El gestor de paquetes estándar de JavaScript: descarga, actualiza y administra las librerías del proyecto. Se instala junto con Node.js.

npx

Herramienta integrada con npm que permite ejecutar paquetes directamente, sin necesidad de instalarlos de forma global en el equipo.

Visual Studio Code

Editor de texto y entorno de desarrollo integrado (IDE) recomendado por la comunidad. Incluye una terminal integrada que usarás constantemente.

Resumen de la sección React pone las piezas; Next.js pone la estructura, el enrutamiento y el renderizado en servidor; Node.js y npm son el motor que permite instalar y ejecutar todo lo anterior.

Desarrollo práctico, buenas prácticas y proyecto integrador

Aquí pasas de observar a construir. Harás tres ejercicios progresivos y terminarás con una tarjeta de presentación interactiva.

Ejercicio 1 · Tu primer componente interactivo

Objetivo: crear un componente que reaccione a un clic del usuario.

Idea clave: en el App Router, los componentes son de servidor por defecto. Para usar estado (useState) y eventos, el archivo debe empezar con la directiva 'use client';.

Pasos:

  1. Dentro de src/app/, crea un archivo nuevo llamado BotonLike.tsx.
  2. Copia el siguiente contenido completo.
  3. Guarda el archivo con Ctrl + S.
src/app/BotonLike.tsx
'use client';

import { useState } from 'react';

export default function BotonLike() {
  const [likes, setLikes] = useState(0);

  return (
    <button
      onClick={() => setLikes(likes + 1)}
      className="rounded-xl bg-cyan-500 px-5 py-3 font-semibold text-slate-950 hover:bg-cyan-400 transition"
    >
      Me gusta ({likes})
    </button>
  );
}

Qué hace cada pieza:

  • 'use client'; marca el componente como componente de cliente, habilitando interactividad.
  • useState(0) crea una variable de estado likes que empieza en cero, junto con su función de actualización setLikes.
  • onClick ejecuta la función cuando se pulsa el botón y suma uno al contador.
  • Las clases className son utilidades de Tailwind CSS.

Resultado esperado: al pulsar el botón, el número entre paréntesis aumenta sin recargar la página.

Ejercicio 2 · Crear una ruta nueva

Objetivo: añadir la página /acerca-de.

Regla del App Router: cada carpeta dentro de src/app/ que contenga un archivo page.tsx se convierte automáticamente en una ruta.

Pasos:

  1. Crea la carpeta src/app/acerca-de/.
  2. Dentro, crea el archivo page.tsx.
  3. Copia el contenido y guarda.
  4. Visita http://localhost:3000/acerca-de en el navegador.
src/app/acerca-de/page.tsx
export default function AcercaDe() {
  return (
    <main className="flex min-h-screen flex-col items-center justify-center bg-slate-900 p-6 text-white">
      <h1 className="text-3xl font-bold text-cyan-400">Acerca de</h1>
      <p className="mt-3 text-slate-300">Esta página vive en /acerca-de.</p>
    </main>
  );
}
Detalle importante No necesitas tocar ningún archivo de configuración de rutas. Crear la carpeta y el archivo es suficiente.

Ejercicio 3 · Proyecto integrador: la «Dev Card»

Objetivo: reemplazar la página de bienvenida por una tarjeta de presentación dinámica.

Pasos:

  1. Abre src/app/page.tsx.
  2. Borra todo su contenido por defecto.
  3. Sustitúyelo por el siguiente ejemplo funcional e interactivo.
  4. Guarda el archivo con Ctrl + S.

        </p>

          href="https://nextjs.org"
          target="_blank"

Resultado esperado: una tarjeta centrada, con borde, sombra, título en cian y un botón que abre la documentación oficial en una pestaña nueva.

Buenas prácticas de arquitectura y código limpio

Nombres que revelan la intención

Si necesitas un comentario para explicar qué hace una variable, el nombre ha fallado. Prefiere elapsedTimeInDays a d.

Funciones pequeñas

Una función debe hacer una sola cosa, hacerla bien y que sea lo único que haga. Menos de veinte líneas es una buena referencia.

Un componente, una responsabilidad

Si no puedes describir un componente sin usar «y», probablemente haya que dividirlo.

Elimina duplicados

Si copias y pegas el mismo bloque tres veces, extráelo a un componente reutilizable.

Sin código comentado

El historial de Git conserva lo que borras. El código comentado solo confunde y envejece mal.

Regla del Boy Scout

Deja el código un poco más limpio de lo que lo encontraste, aunque solo añadas una línea.

  );
}

Importante: la ruta de importación empieza por ./ porque el archivo está en la misma carpeta. Con el alias por defecto también podría escribirse @/app/BotonLike.

Ejercicio C · Cambia los colores de la Dev Card

Solución: sustituye las clases de Tailwind por otras. Por ejemplo, cambia bg-slate-800 por bg-indigo-950 y text-cyan-400 por text-emerald-400.

Tailwind aplica las clases que escribes en el atributo className. Al guardar, el cambio aparece al instante en el navegador.

Lista de comprobación de la práctica

33 preguntas y respuestas

Divididas en tres niveles: básico, avanzado y PRO. Pulsa cada pregunta para desplegar la respuesta.

Nivel básico (11 preguntas)

1. ¿Qué es React y para qué sirve?

React es una librería de JavaScript orientada a la creación de interfaces de usuario interactivas y reutilizables mediante componentes. Sirve para construir pantallas a partir de piezas independientes que se pueden reutilizar en cualquier parte de la aplicación.

2. ¿Qué es Next.js y en qué se diferencia de React?

Next.js es un framework sobre React que ofrece características listas para producción como renderizado en servidor, enrutamiento por carpetas y optimizaciones automáticas. React es la librería de componentes; Next.js es el marco completo que la rodea.

3. ¿Por qué es necesario instalar Node.js antes de usar Next.js?

Node.js proporciona el entorno para ejecutar las herramientas de construcción de JavaScript y gestionar los paquetes de dependencias requeridos por la aplicación.

4. ¿Qué es npm y qué función cumple?

npm es el gestor de paquetes por defecto de Node.js, encargado de descargar, actualizar y administrar las librerías del proyecto.

5. ¿Qué diferencia hay entre npm y npx?

npm sirve para instalar paquetes en el proyecto o en el equipo, mientras que npx ejecuta un paquete o herramienta directamente sin obligar a su instalación permanente.

6. ¿Qué comando se usa para iniciar el asistente de creación de Next.js?

El comando oficial es npx create-next-app@latest.

7. ¿Para qué se utiliza el comando cd en la terminal?

cd (Change Directory) permite navegar entre diferentes carpetas desde la línea de comandos, es decir, cambiar el directorio de trabajo actual.

8. ¿Qué comando arranca el servidor local de desarrollo?

El comando es npm run dev.

9. ¿Cómo se abre la vista previa en el navegador desde la terminal de VS Code?

Presionando la tecla Control (o Cmd) y haciendo clic directo sobre el enlace URL emitido por la terminal (localhost:3000). También se puede copiar la dirección y pegarla en el navegador.

10. ¿Cómo se detiene la ejecución del servidor de desarrollo local?

Mediante la combinación de teclas Control + C en la terminal.

11. ¿Qué función cumple el archivo src/app/page.tsx?

Es el componente que representa visualmente el contenido de la página inicial o raíz de la aplicación.

Nivel avanzado (11 preguntas)

12. ¿Qué ventaja ofrece seleccionar TypeScript durante la instalación?

Proporciona detección de errores de tipos en tiempo de compilación, mejorando el autocompletado y la robustez del código.

13. ¿Para qué sirve Tailwind CSS en un proyecto de Next.js?

Permite diseñar la interfaz de forma rápida aplicando clases utilitarias directamente dentro de las etiquetas TSX, sin escribir CSS extenso manualmente.

14. ¿Qué es y para qué se usa ESLint?

Es una herramienta de linter que analiza el código en busca de errores potenciales y hace cumplir convenciones de estilo de código.

15. ¿Qué significa la opción de colocar el código en una carpeta src?

Permite separar el código fuente del proyecto de los archivos de configuración en la raíz, logrando una estructura organizada.

16. ¿Qué es el App Router de Next.js?

Es el sistema moderno de enrutamiento basado en archivos e impulsado por React Server Components, introducido a partir de Next.js 13.

17. ¿Para qué sirve el archivo src/app/layout.tsx?

Define la plantilla global y persistente (HTML base, body, fuentes y metadatos) que envuelve a todas las páginas de la aplicación.

18. ¿Qué sucede si respondes «No» a la opción de Turbo pack en el asistente?

Se utiliza el empaquetador estándar (Webpack) para el servidor de desarrollo, garantizando máxima estabilidad probada.

19. ¿Qué son los alias de importación (@/*)?

Son atajos configurados en TypeScript para importar módulos desde la raíz src/ sin usar rutas relativas largas como ../../components.

20. ¿Qué significa que un archivo tenga la extensión .tsx?

Indica que el archivo contiene sintaxis de React (JSX) combinada con comprobaciones de tipo de TypeScript.

21. ¿Qué es el Hot Module Replacement (HMR) o Fast Refresh?

Es la característica que actualiza los cambios de código instantáneamente en el navegador sin perder el estado del componente ni requerir recargar la página manualmente.

22. ¿Dónde se almacenan las dependencias descargadas por npm?

Se guardan en el directorio node_modules/, dentro de la raíz del proyecto.

Nivel PRO (11 preguntas)

23. ¿Qué diferencia a los React Server Components (RSC) de los Client Components?

Los RSC se ejecutan y renderizan exclusivamente en el servidor, reduciendo el tamaño del paquete JavaScript del cliente, mientras que los Client Components se ejecutan en el navegador e incorporan interactividad (useState, useEffect).

24. ¿Cómo se convierte un componente de servidor en un componente de cliente en Next.js?

Añadiendo la directiva 'use client'; en la primera línea del archivo correspondiente.

25. ¿Cómo gestiona Next.js la optimización de fuentes tipográficas?

A través del módulo next/font, que descarga y aloja automáticamente las fuentes en el servidor durante la compilación para evitar peticiones externas y mejorar el rendimiento.

26. ¿Qué archivo en Next.js permite personalizar los metadatos SEO dinámicos?

Los metadatos se definen exportando un objeto de tipo Metadata dentro de los archivos layout.tsx o page.tsx.

27. ¿Cómo se crean subrutas anidadas dentro del App Router?

Creando carpetas dentro de src/app/ (por ejemplo, src/app/contacto/) e incluyendo dentro de ellas un archivo page.tsx.

28. ¿Qué utilidad tiene el archivo package.json?

Contiene los metadatos del proyecto, los scripts ejecutables (dev, build, start, lint) y la lista exacta con las versiones de las dependencias instaladas.

29. ¿Qué es el archivo package-lock.json y por qué no debe borrarse ni editarse a mano?

Registra el árbol de dependencias exacto e inmutable instalado en un momento dado, garantizando que el proyecto se instale de forma idéntica en cualquier equipo. Editarlo a mano puede romper esa garantía.

30. ¿Cómo se maneja el renderizado de imágenes de forma optimizada en Next.js?

Mediante el componente de imagen optimizado de next/image, que redimensiona, optimiza formatos y aplica carga perezosa (lazy loading) automáticamente.

31. ¿Qué hace el comando npm run build?

Compila y optimiza la aplicación para entornos de producción, generando los artefactos necesarios para el despliegue final.

32. ¿Qué plataforma se recomienda oficialmente para desplegar aplicaciones Next.js?

Vercel, la plataforma de alojamiento creada por los mismos desarrolladores de Next.js, que ofrece despliegues automáticos desde Git.

33. ¿Cómo se definen variables de entorno en Next.js de forma segura?

Creando un archivo .env.local en la raíz del proyecto y utilizando el prefijo NEXT_PUBLIC_ únicamente en las variables que se requieran exponer al lado del cliente.

Guía de solución de problemas y errores frecuentes

Los errores son información, no fracasos. Antes de tocar nada, lee el mensaje completo: casi siempre indica el archivo, la línea y el motivo.

EADDRINUSE: port 3000 is already in use Ya hay otro servidor o proceso ejecutándose en el puerto 3000. 1. Vuelve a la terminal donde arrancaste el servidor.
2. Detén el servidor anterior con Ctrl + C.
3. Arranca de nuevo con npm run dev.
4. Si sigue ocupado, acepta cambiar al puerto 3001 cuando la terminal lo pregunte.
'node' no se reconoce como un comando Node.js no se instaló correctamente o no se añadieron sus variables de entorno. 1. Reinicia Visual Studio Code.
2. Si persiste, reinstala Node.js desde su sitio web oficial.
3. Asegúrate de descargar la versión LTS.
4. Vuelve a comprobar con node -v.
Errores de sintaxis o de tipo en TypeScript Declaración incorrecta de variables o tipos incompatibles. 1. Revisa las sugerencias que el editor resalta en rojo.
2. Lee el mensaje completo: indica archivo y línea.
3. Consulta la sintaxis recomendada en la consola.
4. Corrige y guarda: la recarga es automática.
El navegador muestra una pantalla blanca o un error 404 Error al renombrar o borrar archivos estructurales como layout.tsx. 1. Asegúrate de no mover ni eliminar los archivos clave dentro de src/app.
2. Comprueba que existe src/app/page.tsx.
3. Detén el servidor con Ctrl + C y vuelve a arrancarlo.

Otros avisos habituales al seguir esta guía

Estos avisos no aparecen literalmente en la guía original, pero se derivan de ella y de sus propias recomendaciones.

«Could not create a project called "mi app" because of npm naming restrictions»

Causa: npm no admite espacios ni mayúsculas en los nombres de paquete.

Solución: vuelve a ejecutar npx create-next-app@latest y escribe el nombre en minúsculas y sin espacios, por ejemplo mi-app.

La terminal dice que no encuentra el archivo o la carpeta

Causa: la terminal está situada en un directorio distinto del que esperas.

Solución: usa cd para entrar en la carpeta correcta y comprueba que dentro existe el archivo package.json. Los comandos npm deben ejecutarse siempre dentro de la carpeta del proyecto.

Guardo cambios y el navegador no los muestra

Causa: puede tratarse de un problema de caché de Next.js o de que el archivo guardado no es el que crees.

Solución: comprueba la ruta del archivo en la barra del editor, recarga el navegador con F5 y, si persiste, detén el servidor con Ctrl + C y vuelve a ejecutar npm run dev.

Cambio algo en page.tsx y la página se queda igual

Causa: es frecuente haber editado el archivo equivocado o no haber guardado.

Solución: confirma que el archivo abierto es src/app/page.tsx, guarda con Ctrl + S y observa si en la terminal aparece el mensaje de recompilación.

Cómo leer un mensaje de error

  1. Busca el archivo y la línea. Casi todos los mensajes incluyen algo como ./src/app/page.tsx:12.
  2. Lee la última línea primero. El resumen del error suele estar al final del bloque.
  3. No cambies diez cosas a la vez. Corrige una, guarda y comprueba.
  4. Deshaz si empeora. Vuelve al último estado que funcionaba antes de seguir investigando.

Resumen, glosario y listas de comprobación

Resumen por capítulos

Introducción y fundamentos

React es la librería de componentes; Next.js es el framework que añade enrutamiento, renderizado en servidor y herramientas listas para producción. El App Router de la carpeta src/app usa React Server Components por defecto.

Requisitos previos

Node.js LTS (que incluye npm), Visual Studio Code y su terminal integrada. El comando cd sitúa la terminal en la carpeta de trabajo.

Inicialización

npx create-next-app@latest abre un asistente de ocho preguntas. En esta guía: nombre del proyecto, TypeScript sí, ESLint sí, Tailwind sí, carpeta src sí, App Router sí, Turbo pack no, alias por defecto no.

Estructura de archivos

layout.tsx es el contenedor global; page.tsx es el contenido de la ruta raíz; globals.css contiene los estilos globales. En la raíz viven los archivos de configuración.

Servidor de desarrollo

npm run dev arranca el servidor. Se abre con Ctrl + clic sobre la URL y se detiene con Ctrl + C.

Práctica

Componentes de cliente con 'use client';, rutas creadas con carpetas y page.tsx, y una Dev Card construida con Tailwind CSS.
